# gb-1020 测试记录（补报 / 更正 / 固定基准重算）

本环境无 Docker、无 fastapi/sqlalchemy/numpy 等运行时依赖，因此本记录只覆盖可在纯标准库
Python 3.11 下执行的单元与端到端检查；真实容器、权限、页面与截图验收需在具备
`docker compose` 的环境补做，未执行项不在此记为通过。

## 已执行：单元测试

命令（工作目录 `backend/`）：

```
python3 -m unittest discover -s ../test-artifacts/gb-1020/tests -p 'test_*.py' -v
```

结果：20 个用例全部通过（Ran 20 tests … OK）。覆盖点：

- 单行校验：缺字段、非有限值/布尔值、计划分钟越界、实播/停播超计划、非法 ISO 日期、空链路。
- 首次接入：干净批次全量并入并写批次留痕；坏记录逐条列明原因且不混入有效记录；
  同批同链路同日的重复与冲突分别拒收。
- 补报合并：晚到播出日按（链路，播出日）并入；完全重复内容计入忽略且结果不变；
  同日较新修订覆盖旧版；多链路各自独立合并。
- 旧修订保护：带 `replaces_revision` 的迟到旧版在当前已有更新修订时只计入忽略、
  不是坏记录、不回滚结果，内部控制字段不进入业务记录。
- 坏记录隔离：补报中的坏记录拒收并带批次序号，其余好记录正常并入。
- 核对恒等式：跨批次满足 累计接收 = 并入/修订 + 忽略 + 拒收。
- 固定基准重算：更正基准期内历史日会改变 μ/σ 与后续越限判断，但窗口仍是最初30日；
  更正监测期数据不改变 μ/σ，只沿 EWMA 递推重算后续越限；未来值永不参与基准估计。

## 已执行：端到端脚本（纯标准库，直接调用服务层）

用 `seed_records()` 的 360 行真实结构数据，依次验证：首次接入 → 补报含
更正/新播出日/重复/坏记录 → `analyze` 重算 → 旧修订补报被忽略 → 对外字段剥离。

实测结果：

- 补报 4 条：并入/修订 2、忽略 1、拒收 1；汇总恒等式 balanced=True；有效记录 361 行。
- 新闻一频 completion 口径：基准均值 99.3981、基准标准差 0.1334 在更正前后完全不变；
  越限日数由 20 变为 22（受影响链路后续判断已重算）。
- 旧修订补报后再次分析，metrics 与 chart 与当前版本逐字节一致。
- `public_records` 输出仅含六个业务字段，无 `_revision` 等内部留痕。
